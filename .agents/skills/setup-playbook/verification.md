# Verification

`verify-<app>` is this project's skill for driving the running app the way a user does, generated by `/create-verification-skill` into `.claude/skills/verify-<app>/`. These rules apply once it exists.

- Run `verify-<app>` in a subagent. Brief it with what changed (or the bug report) and which journeys from its feature map to drive; it returns pass/fail per journey, evidence paths, and any gaps it hit.
- When `implement` or `implement-spec` finishes a ticket, drive the change with `verify-<app>` before calling the ticket done. Under `implement-spec`'s parallel worktrees, drive per worktree when the skill's Isolate section allows side-by-side instances; otherwise drive once on the integration branch after the merge.
- When `pr` writes its evidence, take it from a `verify-<app>` run.
- When `triage` reproduces a bug or `diagnosing-bugs` builds its feedback loop, start from `verify-<app>`'s Drive section; build an ad-hoc harness only for what it cannot reach.
- When a ticket adds or changes a user journey, update `verify-<app>/features/` in the same change.
- At the end of `retro`, suggest the user run `/maintain-verification-skill` in a new session, and mention it can also run on a schedule.

## Reading the pstack skills in Claude Code

`/create-verification-skill` and `/maintain-verification-skill` are written for Cursor. Read their Cursor names as:

- `.cursor/skills/` → `.claude/skills/`
- read-only subagent → `Explore` subagent
- "one PR" → open it with the `pr` skill
